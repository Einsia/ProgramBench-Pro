# StackEdit coverage

Version 1.0.0, reference StackEdit 5.15.4. The executable manifest defines 102 episodes (55 program, 47 GUI), 1,292 checkpoints and 1,533 points: 273 frontend and 1,260 backend. `data/manifest.json` is the frozen count authority.

## Observation and comparison

Every setup, stimulus and observation uses the same documented runtime available to the candidate. Rich HTML paste uses a normal browser ClipboardItem and Ctrl+V; both evaluator and candidate can supply it, and the application performs its own conversion. There is no direct filesystem, Vuex, IndexedDB or internal-service access. Program checkpoints reset independently, open their input through the real embedding interface, optionally operate the focused editor, and read its genuine `fileChange` message. Failures affect only the current point; the shared driver restarts crashed products before continuing.

GUI checkpoints prepare only source and selection through generic editor input. GUI-created prerequisites are scored as explicit goals, followed by checkpoints that declare the state they continue and their dependencies. Candidate preparation never invokes the reference navigation recipes. Temporary files and light-editor inputs use the documented embedding interface. Reference recipes use only the same public operations. The replacement helper verifies exact reference input, so automatic list continuation cannot silently alter the fixture. Program companions read the visible source, reopen that source through the public embedding interface when semantic Markdown comparison is needed, or retrieve the file the user operation generated. Workspace backup projections cover document names, folder paths, contents and parsed YAML properties, without IDs or timestamps. Round trips transfer the exact bytes of a public download to the next checkpoint’s ordinary input-file list; the evaluator uses the same runtime upload operation as for supplied fixtures. This is file transfer, not a product-state shortcut. GUI source companions apply only when exact content is specified by the goal.

HTML is parsed as data. Checks compare element semantics, nested content, significant code whitespace, links, image attributes, table alignment, checkbox state and math placeholders. They normalize `b`/`strong`, `i`/`em`, equivalent strikeout tags, emphasis nesting order, incidental block/table wrappers, collapsed ASCII layout whitespace, attribute ordering, generated anchor identities and equivalent anchor fragments. Text-flow normalization preserves word-separating spaces, nonbreaking spaces, line-break elements and code whitespace. HTML-import companions compare rendered semantics rather than a particular Markdown delimiter style. Explicit conversion-setting goals additionally verify the requested syntax family. Plain-text exports preserve every newline; styled exports require CSS supplied by a stylesheet or inline styling; TOC exports verify links against matching headings; Jekyll front matter is parsed as typed YAML. Semantic attributes must match; additional fields in application metadata objects are ignored. No HTML is executed by the verifier.

The runtime initializes the browser clock at 2024-01-15T12:00:00Z and lets time advance normally, preserving undo grouping and persistence timers. Rendering and finite animations settle before observations. Reference preparation waits for the initial offline notice to expire, without suppressing errors caused by a goal. Select options are exposed by their visible labels, so generated template IDs do not enter evidence. Random-number calls use a fixed seed; generated document IDs remain omitted by the embedding projection. Screenshots may differ in anti-aliasing, caret blink and selection focus; these are not acceptance criteria.

## Exclusions

| Feature | Reason |
| --- | --- |
| Google sign-in, sponsorship, cloud synchronization and publication (Google Drive, Dropbox, GitHub, GitLab, Gist, Blogger, WordPress, Zendesk, CouchDB and Google Photos) | Require network services, authentication and external state; the reference and verifier are offline. Account/provider-dependent history, collaboration and comments have the same limitation. The product requires Google sign-in before commenting. |
| PDF and Pandoc conversion, and the corresponding wkhtmltopdf/Pandoc settings | Depend on the product’s authenticated/sponsored server conversion service; not part of the local static editor. |
| Browser/OS printing | Headless Chromium does not expose an interactive system print dialog through this runtime; document HTML export is covered. |
| Custom Handlebars template execution and JavaScript helpers | Product templates compile and execute code. The runtime rejects non-built-in template execution and nonempty helper scripts at the worker boundary (configuration/isolation requirement). Template definition management remains covered. |
| Remote images, linked pages, service-worker installation, Chrome app/extension and embedding in arbitrary outside origins | Depend on network, browser installation or additional applications. The existing embedding message interface is covered directly at the local product origin; data images remain available. |
| Seven-day automatic Trash expiry and periodic cloud synchronization timers | Require elapsed days or an online service. Immediate Trash/restoration and reload persistence are covered; the browser clock has a fixed starting instant. |
| Exact scrolling/animation trajectories and draggable pane-divider behavior | Focus mode, scroll synchronization and contents navigation are covered using distinct final positions in a long document. Exact animation paths are incidental. Version 5.15.4 has no draggable source/preview divider: its public layout gives each pane half of the available width; it exposes visibility and text-width controls instead. |
| Rename/properties dialogs inside the light embedding editor | The light editor hides those controls. Editing and fresh embedding messages are covered; names and properties are supplied and replaced via the genuine fragment interface, and ordinary-editor management is covered separately. |
| Audio playback/MIDI interaction of ABC notation | Requires an audio device/output inspection; staff rendering is covered. |

## Budgets

Each GUI episode has `min(400, 40 + 35 × checkpoints)` model calls, `min(8,000,000, 600,000 + 600,000 × checkpoints)` cumulative tokens, and `400 + 300 × checkpoints` active seconds. The basic and structured backup episodes have 250 calls and 4,000,000 tokens; invalid-backup cases have 180 calls and 3,000,000 tokens to retain headroom for import/export operations. The diagram-rendering episode has 7,200 active seconds. Counts include explicitly scored prerequisite checkpoints. Program episodes use no model.

The shared runner freezes each episode’s reference duration and derives program limits as `max(900 s, 5 × duration)` and GUI limits as budget seconds plus `max(600 s, 5 × duration)`. The task verifier timeout is at least 1.1 times the sum of episode limits plus launch allowances, and at least 86,400 seconds. Provider waiting time is excluded from active episode time; provider outages invalidate the run.
